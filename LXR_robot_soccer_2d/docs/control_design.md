# 4.1 二维运动控制与导航验证

这套验证使用 20 ms 的仿真步长。Python 默认对每一步执行联合限幅，`--control-design` 额外启用基于感知的局部导航。只有历史 MATLAB 轨迹对照测试显式使用旧限幅。

## CTL-02、CTL-03：目标点引导与速度执行

1. `walk_to` 把目标位置减去当前估计位置，并把误差旋转到机器人坐标系（前方为 x、左方为 y）。平移指令等于位置误差乘以 `1.5 s⁻¹`，转速指令等于最短朝向误差乘以 `2.5 s⁻¹`。
2. 小误差、无遮挡且不受限幅与加速度约束时，一阶近似的时间常数分别为约 **0.67 s** 和 **0.40 s**。大误差会引起饱和，同时平移、侧移和转向会分担速度余量。平移加速度限制会延迟起步与制动，快速换目标时可能出现超调。
3. 运动层先将目标指令缩放进联合上限，再限制相邻两步的平移速度变化 `‖Δv‖ ≤ accel × dt`，最后用本步实际平移速度剩下的余量限制转速。前进与后退使用不同上限。此模型没有角加速度参数。进入踢球动作时立即锁住位置和朝向，此时步行加速度检查暂停。
4. 单独改 `walk_to` 的 `position_gain` 和 `heading_gain` 可以比较增益。在前锋从 `(0, 0)`、初始朝向 `0.7 rad` 走向 `(1, 0)`、最终朝向 `0 rad` 的空场算例中，低增益 `(0.75, 1.25)`、默认增益 `(1.5, 2.5)`、高增益 `(3, 5)` 的到位用时分别为 **6.12 s、5.08 s、4.78 s**。这三次均未越过目标 x 坐标。保留原增益，用于复现实验及后续带感知噪声的对照。

## CTL-05：分角色指标

参考项目规格第 2 页的角色职责。先由进攻或防守任务规定机会窗口与成功事件，再用同一组窗口评估控制器。空场点到点测试中的 `5 cm`、`5°`、`7–8 s` 只是 **CTL-03 回归阈值**，不作为角色验收标准。

| 角色任务 | 时间指标的来源 | 几何和结果指标的来源 |
|---|---|---|
| 门将挡住射向球门的地滚球 | 在无遮挡参考轨迹第一次到达门将拦截线前进入挡球位置。用 `ball_path` 从开球点和球速计算时限。只纳入能到达门线且穿过门框的来球。 | 门将站在拦截线上时，横向偏差必须小于机器人半径与球半径之和（当前为约 `0.227 m`）才会发生圆形接触。记录首次触球、是否阻止进球。二维身体为圆形，因此不规定挡球朝向。 |
| 后卫封住进入保护区的传球路线 | 按战术指定保护线。球在无遮挡参考轨迹中第一次越过该线前，后卫要进入有效封堵位置。 | 以球在保护线的交点为目标，中心距须小于机器人与球的半径之和才覆盖交点。记录封堵后球是否进到保护区。若球路本身不会到达保护线，该场景不计入封堵成功率。 |
| 前锋在对手抢到球之前射门 | 给定对手起点和能力上限，以对手最早触球时间减去前锋启动踢球到实际触球的延迟，得到最晚出脚指令时间。 | 触球时球必须处于脚可达半径内，并落在身体前方的踢球扇区；射门方向必须在可执行范围内。用真实触球和球是否越过门线且整球在两门柱内判断结果。记录触球时间和无干扰射门的横向门线偏差。 |

可复算的二维场景示例：

- **门将。** 门将在 `(-4.1, 0)`，球从 `(-2.6, 0.60)` 以 `(-2.0, 0) m/s` 朝本方球门滚动。球约 `0.97 s` 到达拦截线。即使门将一直以 `0.25 m/s` 平移，最多也只能移动约 `0.24 m`，小于进入挡球范围至少需要的 `0.37 m`。该开局在当前模型下达不到要求，应检查门将提前站位和可覆盖范围，不能把到位时限放宽到 `7 s`。
- **后卫。** 若保护线是 `x = −3.0 m`，球从 `x = −2.0 m` 以 `−1.4 m/s` 沿 x 方向滚动，则实际封堵窗口约 `1.02 s`。起始横向位置和球路决定需移动的距离。
- **前锋。** 若对手头朝球、距静止球 `1.20 m`，并假设可马上以 `0.25 m/s` 前进，对手在达到脚可及距离 `0.327 m` 时最早触球。扣除前锋 `0.50 s` 的踢球启动延迟，出脚指令须在约 `2.99 s` 内发出。对手初始距离变化，窗口随之变化。

这些是基于明确场景的指标和可达性推导。保护区域、来球和对手开局的分布、最低成功率，以及球员能力的 3D 标定仍待团队确认。现有专项测试不能证明这些比赛指标已满足。

## CTL-04：基于局部感知的自主导航

`navigate_to` 根据 `Percept` 中的自身估计位置、队友位置和对手位置规划。直线路径受阻时，先尝试一个绕行点，再尝试连接多个绕行点。规划时把目标和绕行点限制在球场内，优先与可见球员中心保持 **0.41 m**（两个圆形半径加 0.10 m 余量）。起点已在余量内时，允许侧移或退开，条件是这一段路线不进一步靠近该球员。找不到完整路线时尝试可走的局部一步；目标被占用时可先靠近安全位置，利用后续感知重算。

规划器没有访问 `World` 或真实球员状态。单元测试直接构造 `Percept` 来隔离控制误差，真实坐标只用于计算测试误差和最小距离。4 对 4 可用默认的 `realistic` 感知来运行；模型仍不能保证遮挡、多障碍移动或处于近球脚位对齐阶段时避开碰撞。裁判重开球和近距离脚位对齐沿用各自的处理。碰撞分离是仿真层行为，不能算自主避障成功的证据。

## 验证命令

在 `code/python` 运行：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_control.py' -v
.venv/bin/python -m robot_soccer.simulations.match --control-design --seconds 120 --seed 1
```

`test_control.py` 覆盖前进、后退、双向侧移、双向原地转身、踢球触球时刻和固定目标点到达。联合上限在突然换向和两种比赛模式中逐步校验。避障场景包括对手贴近边线、队友在身体近处、两名球员错位阻挡，以及目标被占用后移开。绕行测试不启用碰撞分离。普通绕行检查 `0.41 m` 中心距，已处于余量内的场景检查机器人能到达目标且不发生圆形碰撞（中心距至少 `0.31 m`）。
