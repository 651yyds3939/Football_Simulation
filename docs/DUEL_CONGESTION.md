# 一攻一防贴身僵持排查

本页记录卡球修正那一版的对照。后续的回防响应见 [回防响应排查](DEFENSIVE_RECOVERY.md)，当前近距离对抗及阈值更新见 [封堵与断球验证](DEFENSIVE_CHALLENGE.md)。

## 现象与原因

界面时间推进，但球停在两台机器人之间；红方在 `MAKE_FOOT_SPACE` 和带球之间反复切换，蓝方重复解围，触球次数增加但没有有效推进。

1. `tools/soccer2d.py` 原碰撞处理把本步位移截断到第一次碰撞点，再反射速度。当碰撞比例为零，整步位移被丢弃；下一次带球或踢球又遇到相同碰撞，球可能固定在完全相同的坐标。这是二维执行器问题，不是 Webots 或浏览器崩溃。
2. 共用策略缺少长时间贴身争球后的让位动作。反复要求直推或解围，不能保证足球摆脱另一台机器人的身体范围。
3. 二维使用重叠可能的圆盘近似身体和脚部接触，不包含 NAO 真实脚形、身体姿态或倒地。修正碰撞算法后仍会存在模型内的僵持。

截图没有显示种子。排查从运行中的本机服务保存了一份观测，使用该观测的随机种子 `309071988` 复现了同类问题，不能把它称为截图那一轮的精确复现。

## 保留的修改

| 程序 | 修改 | 适用范围 |
| --- | --- | --- |
| `tools/soccer2d.py` | 碰撞反弹后继续消耗本步剩余位移，最多处理 6 次反弹；保留原滚动摩擦、反弹损失和速度参数 | 仅二维执行 |
| `Utils/TeamPolicy.py` | 根据世界时间和位置检测长时间贴身僵持，生成 `DUEL_ESCAPE` 决策 | 二维与 Webots 共用 |
| `Utils/Navigation.py` | 把让位目标转换成身体坐标下的左/右侧移请求 | 二维与 Webots 共用 |
| 二维浏览器界面 | 显示 `Create space / 遇堵让位` 和黄色状态提示 | 只显示 Python 决策 |

让位仅用于当前争球者，比赛需处于允许活动的阶段。条件：自身距球小于 0.45 m，至少一名对手距球小于 0.45 m 且距自身小于 0.42 m，足球连续 8 秒没有离开半径 0.06 m 的参考范围。让位目标距自身侧向 0.12 m，避开贴身对手；单次最多 8 秒，或拥挤条件解除、接近目标时提前结束。边界附近反转让位侧并限制目标在场内。比赛停止、处罚或不再负责争球时清除相关历史。

这些阈值是策略假设，不是课程标准或真机标定。没有提高动作速度、直接重置球的位置、删除对手或强制判成功。让位仍可能失败；相同输入历史下，二维与三维使用相同规则，但执行轨迹不同。

## 对照测试

两版均为随机开局、180 秒上限、guarded/centre 配置。原版快照在更新打包前用于基线测试，结果及源代码哈希保存在工作区 `verification/one-v-one-20261111/`。

| 种子范围 | 版本 | 红方进球 | 蓝方进球 | 超时 |
| --- | --- | ---: | ---: | ---: |
| 27–46，共 20 次 | 修改前 | 14 | 0 | 6 |
| 27–46，共 20 次 | 修改后 | 16 | 3 | 1 |
| 47–146，另 100 次 | 修改前 | 72 | 0 | 28 |
| 47–146，另 100 次 | 修改后 | 82 | 5 | 13 |

蓝方进球也代表该模型内成功结束了一次攻防，不能只以红方进球评价是否改善僵持。种子 `37` 在最终版本仍超时，保留了完整 JSON 与 HTML 回放作为失败用例。实际服务捕获的种子 `309071988` 从原来的 180 秒超时变为约 87 秒红方进球。

先单独修正碰撞时，20 个种子的超时从 6 次降到 5 次；再加入短暂侧移后降到 1 次。因此最终前后差异包含执行器和策略两部分，不能全部归因于策略。试验过主动斜向绕行、先后退再侧移，两者在这批种子上不如保留版本，未保留到默认策略。

以上是模型内部验证，不是一般性的攻防成功率，也不说明真实防守或进攻已经可靠。更广的 100 个种子仍有 13 次超时，需要继续分析卡球几何、重复踢球和绕行。

## 已验证和未验证

- 89 项单元与回归检查通过，覆盖静止拥挤触发、移动球不误触发、无对手不误触发、让位时限和比赛中断清理、时钟重置、反弹后位移以及踢球向外不撞回自身。
- 浏览器检查覆盖 Python 实际触发让位、中英文状态显示、门前射门、批量运行、拖动开局、HTML 回放和移动端排版。
- 更新策略后的 12 秒 Webots 门前接口用例运行完成，95 条实际决策请求重算一致。该用例没有触发贴身让位，不能据此宣称三维侧移不摔倒或三维僵持已解决。
- Windows 启动脚本仍包含在便携包内；尚未在真实 Windows 系统上实测。

## 复测操作

停止旧 Python 服务并重启，打开终端新打印的网址。设置随机场景、种子 `28`、时长 `180`，观察贴身接触后状态变为 `Create space`，再观察后续攻防。种子 `37` 用于观察剩余失败。

批量测试示例，在仓库根目录运行：

```bash
python ../2D_Shared_Policy_2026-11-11/server.py --batch 20 \
  --scenario random --seed 27 --seconds 180 --locomotion guarded \
  --output runs/duel_congestion_01
```

输出目录必须尚不存在。保留原有失败数据，下一次修改仍用相同种子和配置对照。仅刷新网页不能重新加载 Python 进程已导入的策略。
