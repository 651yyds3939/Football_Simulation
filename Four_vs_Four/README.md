# 2D 四对四机器人足球

## 直接看

双击 `demo.html`，用 Chrome 或 Edge 打开英文回放。项目根目录还有 [中文回放](../Football_4v4_Demo_ZH.html)。回放可离线播放。该场使用种子 294034，双方均使用 11 月 25 日修订的四对四策略，比分 3:1。

默认32倍，可选最高128倍；支持暂停、拖动进度、逐帧查看和点击球员。“Team targets / 球队目标点”虚线显示实际决策目标，可以关闭。目标点不是走过的轨迹，也不代表已完成传球。

| 回放时间 | 发生的动作 |
| --- | --- |
| 0:33.2 | 红队后卫将球传给红队前锋 B，前锋脚下接球 |
| 0:36.8–0:46.6 | 红队前锋 B 沿侧面带过蓝队前锋 B |
| 1:26.2 | 蓝队门将移动后挡到球 |
| 1:38.6 | 红队进球，八名球员随即回到开球位置 |
| 9:16.2 | 补测中的下半场末段进球 |

11 月 25 日加入拥堵让位。球和周围至少三名球员持续接近静止时，离球较远的球员短暂退出争抢区域，让最近的球员继续处理球。相同 40 个种子复测，场均卡球时间从 51.4 秒降到 48.6 秒，仍有 10 场出现超过 30 秒的卡球。

## 重新运行

安装 Python 3.8 或更新版本，不需要额外 Python 依赖。

- Windows：双击 `start_windows.bat`。
- Ubuntu/Linux：在本目录运行 `bash start.sh`。
- macOS：在本目录运行 `python3 run.py --open`。

程序先全速计算比赛，再打开浏览器回放。128倍下十分钟比赛约五秒播完，比赛实际时长以画面时钟和结果文件为准。

也可以在本目录运行：

```sh
python run.py --open
python run.py --seed 28 --language zh --open
python run.py --red-policy reference --blue-policy coordinated --seed 256058 --language zh --open
python run.py --red-policy coordinated --blue-policy reference --seed 246000 --batch 20 --no-replay
```

- `flow` 为默认策略，双方均使用。支持侧面分球、接球停球、绕行、分层防守与无推动的身体碰撞。
- `coordinated` 使用上一版门将、侧面接应与短传，可和 `flow` 对照。
- `relay` 使用原门将和同一套侧面接应与短传，供门将对照。
- `passing` 使用 11 月 23 日的短传策略，供对照。
- `reference` 使用 11 月 19 日配合版本。
- `previous` 使用更早的配合版本。
- `baseline`：基础TeamPolicy策略。
- `--batch 20 --no-replay`：全速批量计算20个种子，不渲染。

结果自动保存在新建的 `runs/match_时间/` 中：`metrics.json` 为比分和源码哈希，`replay.html` 为回放，`scene.json` 为轨迹。批量模式只给第一场生成回放；`--no-replay` 不记录轨迹。修改代码后需要重新生成，旧HTML不会自动更新。

## 11 月 24 日四对四更新

- 进球后，同一仿真步内将八名球员和球放回开球位置，清除未结束的射门、传球和球权，再进入准备阶段。
- 身体相碰时，限制球员自己的移动命令。仍可退开或沿切线绕行。抢球继续由实际足部接触、球的滚动和挡球碰撞决定。
- 持球队员可以沿对手侧面带球，或者拨球给指定的接应队友。接球队员提前移动，球进入足部窗口才记为脚下接球。另有队友拉开到另一侧或在后方补位。
- 防守方按来球位置分配一人封线、第二人补位。门将提前移动封角，近门时优先移动挡球，获得可用线路时尝试向侧面解围。

`Flow.py` 负责分配攻防任务和规划路线。`TeamNavigation.py` 把路线转换成动作。`soccer2d.py` 执行触球、复位和比赛阶段。`contact_motion.py` 负责限制身体位移并检查接球脚下范围。

新版使用独立的 2D 动作近似，包括边移动边调整朝向、快速拨球和伸脚停球。快速分球最长滚动 1.48 米，常规射门最长滚动 2.47 米，这些是二维模型参数。旧版策略仍可用 `--red-policy coordinated --blue-policy coordinated` 运行。

`--no-replay` 适合全速批测。`--dt .04` 可复查对接触采样更敏感的行为。回放倍速只影响看比赛的时间。

11 月 24 日版本使用 180 个新种子逐场比较双方使用旧版或新版时的表现。0.2 秒步长下，每队每场的指定队友脚下接球从 0.07 次增加到 4.42 次。双方持续近球、球基本停住的累计时间从场均 76.8 秒降到 54.9 秒。新版 273 次进球全部在得分当步复位。

另用 85 个新种子按 0.04 秒步长比较。每队每场脚下接球从 0.07 次增加到 4.42 次，卡球从场均 72.8 秒降到 64.5 秒。新版 121 次进球全部当步复位。两种步长的新批次均未观测到球员在原地站立或转向时被对手推移。

专项布局中，110 个带球绕防守场景的成功次数从 86 增到 102，110 个近门柱来球的漏球次数从 53 降到 45。场边卡住时改为选择界内斜向站位。在复现种子 294103 中，最长卡球从 120.4 秒降到 8.0 秒。完整比赛里仍有个别长卡球，总进球数也少于旧版。数字用于评估二维策略和接触模型。

## 11 月 24 日早期门将对照

门将在来球接近时根据球速和持球队员朝向提前站位。预测滚动球会进入门口时，按现有动作速度估计能否及时接触球，并直接选择前进、后退、横移或站稳。球停下来后恢复常规操作，已经对准脚位时可用现有短踢动作尝试解围。

| 对照 | 原门将 | 新门将 |
| --- | ---: | ---: |
| 300 个近门柱来球，0.04 秒步长，漏球数 | 144 | 90 |
| 同样 300 个近门柱来球，0.2 秒步长，漏球数 | 144 | 76 |
| 300 场四对四，0.2 秒步长，危险区内转身时长比例 | 72.1% | 45.3% |
| 同一批四对四，门前持续卡球平均每场时长 | 4.6 秒 | 11.8 秒 |

近门柱场景随机变化左右门柱、攻守方向、球速和门将朝向。比赛对照每个种子交换红蓝，比分合计 426:414，新版 113 胜、105 负、82 平。另用 0.04 秒步长测试 130 场，新版 51 胜、42 负、37 平，危险区转身比例从 75.3% 降到 44.9%。危险区指球进入距本方底线 1.2 米以内，卡球按门将与对手近球且连续至少 4 秒基本停球估算。

有些来球快于门将能覆盖的范围。双方在门前贴身时仍可能反复触球，导致卡球变多。数据来自 2D 模型，使用简化体积接触和已记录的动作速度。

```sh
python3 run.py --seed 275005 --red-policy relay --blue-policy coordinated --language zh --open
```

这场四对四可查看约 9:47.8 蓝队门将的横移，以及 9:51 后的解围尝试。

## 11 月 24 日侧面接应更新

当双方球员面对面、球连续约 3 秒没有明显移动时，策略评估哪名队友能沿空闲路线从侧面接近球。每次只派一名可及时到达的前锋。正面球员继续争抢，直到队友实际用脚触球并把球带离原位置，才短暂让位。对手推进、比赛暂停或换边会结束当前计划。

短传意图在对脚阶段就交给指定队友，由他提前走到接球位置。传球动作、触球与裁判判定仍由仿真执行。程序参数 `passing` 可运行 11 月 23 日的短传版本，用于与默认的 `coordinated` 对照。

在 150 个有队友位于侧面的对顶专项开局里，25 秒内把球带离原点至少 0.25 米的案例从 21 个增到 74 个。另有 240 个近距离短传专项开局，指定队友脚下接球从 63 次增到 66 次。完整比赛的接应机会取决于实际站位。

完整比赛与上一版对照，每个种子交换红蓝。默认步长 0.2 秒的 300 场为 110 胜、111 负、79 平，0.04 秒步长的 120 场为 45 胜、45 负、30 平。

```sh
python3 run.py --seed 267064 --red-policy coordinated --blue-policy passing --language zh --open
```

## 11 月 23 日更新

`Passing.py` 根据球的滚动距离、球员朝向、到达时间及对手位置，选择短传落点和接应位置。球员在出球前调整朝向。若球只差一点才进入脚下范围，接球球员会小幅前移或侧移，接到球后再推进。后卫在中场有空间时可以带球，受到压力时继续执行原有防守与解围。回放在传球准备阶段标出预定落点，事件列表区分身体碰球与脚下接球。

`metrics.json` 的 `directed_passes` 保存每场传球尝试、两类接触、接球朝向误差与后续推进距离。接球后的推进按朝对方球门的纵向距离计算，最多观察 15 秒，球权变化或裁判重新放球时结束。`directed_pass_totals` 汇总本批次，`scene.json` 保存实际事件和轨迹。

新版在 150 个新种子交换红蓝后的 300 场对照中为 121 胜、83 负、96 平。新版有 45 次指定队友脚下接球，对照有 18 次。新版有 8 次接球后向球门推进至少 0.25 米，对照为 0 次。球员身体重叠时间仍接近。种子 256058 的回放中，蓝方在仿真 6:13.4 接球后推进约 0.72 米。

将步长改为 0.04 秒后，在另外 65 个种子的 130 场对照中，新版为 46 胜、43 负、41 平。指定队友脚下接球 12 次，对照为 2 次。

## 11 月 19 日配合记录

无球队员根据到达时间、对手距离和线路寻找接应点，短暂保持目标，进入争球区时局部让位。补位可以使用原有的倒退、侧移等动作，减少不必要的大转身。短传只在附近队友朝向合适、线路清楚且压力允许时触发；接球队员先准备，实际踢到球后再接近，踢空则取消等待。

守门员保持防线、后卫保护后方仍是正常分工，不会让所有人一起追球。没有提高机器人速度、踢球力量或传球距离。

## 效果和不足

带短传的候选100场对上一轮：31胜32负37平；12次定向传球尝试、11次指定接球队员接触、10次带后续脚下接触。加上比赛阶段保护后的最终版本，在另外30个种子交换颜色的60场中为22胜22负16平，出现6次带脚下接触的短传。

配合有了可执行的短传，但还很少；展示例接球后仍需长时间转向，尚未稳定转化为推进。整体胜率没有明显提升，拥堵和无人近球仍会发生。更细步长的小样本表现也不稳定。二维使用精确位置和简化接触，不模拟摔倒、平衡或相机误差，不能代表Webots或真机成绩。

主要文件：`run.py` 为入口；`TeamTactics.py` 为本轮配合策略；`TeamNavigation.py` 为无球导航和半场重新安装导航；`PreviousTactics.py` 为上一轮对照；`TeamPolicy.py`、`Navigation.py` 为基础决策和执行；`soccer2d.py` 为运动、接触和传球消息状态；`MatchEngine.py` 为阶段、规则和比分。这些Python模块在 `backend/Wenao/controllers/Utils/` 或 `backend/tools/` 中。
